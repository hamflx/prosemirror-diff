## Demand and reproduction

- [Marks and attrs discussion, October 2024](https://discuss.prosemirror.net/t/prosemirror-changeset-how-to-also-see-the-changes-in-marks-and-attrs/7677): a two-snapshot, side-by-side review needs formatting and attribute changes that changeset does not report by default. The maintainer explains the narrower purpose of that library.
- [Custom-node comparison discussion, April 2025–March 2026](https://discuss.prosemirror.net/t/visualize-changes-between-2-tiptap-jsons/8328): users describe custom blocks, alignment and schema-preserving display difficulties. Later replies report partial solutions; this is not evidence that every participant's issue is still unresolved.
- [Suggestions as decorations, June 2026](https://discuss.prosemirror.net/t/suggestions-as-decorations/9027): combining deleted and inserted nodes can violate a single-child container or table assumptions.

These sources establish use cases, not market size. Tiptap Compare already
supports headless comparison; no uniqueness claim is made for that property.

The regression fixture reproduces this repository's current behavior: changing
a link href on unchanged text yields no diffMark, and changing an image src
retains the old attribute in the rendered diff. Neither behavior is changed
here; a separate query returns the missing information.

## Contract and implementation

`compareDocumentMetadata(oldDoc, newDoc)` accepts valid document Nodes from one
schema and returns attrs/marks events with node type, old/new half-open ranges
and detached before/after values. It uses public Node accessors, nodeSize,
Node.check and Mark.toJSON. Reference: the locked prosemirror-model 1.18.1
[Node source](https://github.com/ProseMirror/prosemirror-model/blob/1.18.1/src/node.ts).

The first batch intentionally supports identical structure and text, allowing
text nodes to split/merge at formatting boundaries. Consecutive text runs are
compared at the union of mark boundaries. Non-text children are paired by
position and type. Incompatible content throws instead of silently losing
changes or emitting speculative mappings. Root attrs use content bounds;
other node attrs/marks use node spans. Positions remain UTF-16, including emoji.

This satisfies formatting/link/image-attribute review without creating a
schema-invalid combined document. It requires no diffMark or view instance.
Records overlap when parent and child metadata both change and are not an
executable transaction list. Metadata is acyclic plain data; snapshots are
detached so consumers cannot mutate the source through a result.

Repeated identical blocks are positional correspondences, not stable identity
matches. A swap of identical-text blocks with different attrs is indistinguishable
from two attr edits and is reported as such. Reordering different text or changing
types/counts is rejected. Full content-edit alignment and moves remain future work.

## Acceptance

- Added/removed formatting and href changes with differently split text nodes.
- Overlapping formatting boundaries and UTF-16 positions around emoji.
- Image src/alt and leaf marks, root/block attrs, empty documents, nested strict
  single-child containers, and repeated blocks without guessed move events.
- Exact source preservation and detached result snapshots, nested values and
  object-key-order independence, array-length differences and invalid-data errors.
- Explicit rejection of text/structure changes, invalid inputs and schemas.
- Legacy rendering reproduction and unchanged existing behavior.

## Validation and measurement

```sh
node node_modules/vitest/vitest.mjs run
npm exec --package=typescript@5.9.3 -- tsc --allowJs --checkJs --noEmit --target es2022 --moduleResolution bundler --module esnext --skipLibCheck src/index.js
node node_modules/rollup/dist/bin/rollup -c rollup.config.mjs
node test/benchmark-metadata.mjs
git diff --check
```

The audit includes the new module through src/index.js. No dependencies added.
After integration with the base above: 101 tests passed (20 new metadata
tests and all 81 existing tests); checkJs exited 0 without diagnostics;
UMD/CJS/ESM builds, a CJS metadata-result smoke test and diff --check passed.

The informational benchmark constructs schema and inputs before timing,
warms 3 times, then measures 15 calls including schema validation, traversal
and detached result construction. Each paragraph receives a mark change and
every tenth also an attr change. Node v24.19.0, one process, median/p95:

| Paragraphs | Events | Median ms | p95 ms |
| ---: | ---: | ---: | ---: |
| 10 | 11 | 0.301 | 1.555 |
| 100 | 110 | 0.802 | 1.202 |
| 1000 | 1100 | 6.612 | 8.749 |

This is a baseline for the new API, not a comparison with a full structural
diff or a performance guarantee. Arbitrary depth, huge attribute values and
hostile accessor objects are outside these fixtures; there is no hard deadline.

## Next scope

Prioritize stable node pairing and structural events before claiming arbitrary
snapshot comparison. Define ambiguity and mapping behavior using repeated/custom
blocks. A read-only change list or split-view example can then consume this
result model; collaborative accept/reject semantics are a separate project.
