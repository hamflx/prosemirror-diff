# Official table-model integration

Base: `60423c3f88fc629ece1596cdbbcd6b9f39f8340e`. Investigation date: 2026-10-24.

## Why test a real table schema?

The [custom-node revision discussion](https://discuss.prosemirror.net/t/visualize-changes-between-2-tiptap-jsons/8328)
includes partially successful recursive comparisons, while the
[suggestion rendering discussion](https://discuss.prosemirror.net/t/suggestions-as-decorations/9027)
describes how mixed content can break table assumptions. These are reasons to
verify actual table nodes and preserve original documents, not evidence for
automatic cell identity or a table patch engine.

The integration uses official `prosemirror-tables@1.8.5` `tableNodes` and
`TableMap`, with `prosemirror-model@1.25.12` and `prosemirror-state@1.4.4`. These are isolated test dependencies,
not additions to the library's production dependencies or a claim that every
tables/model version combination is supported.

## Two distinct validity checks

`Node.check()` verifies the model's content and marks/attribute constraints. It
does not certify a rectangular, non-overlapping table grid. Official
[table schema definitions](https://github.com/ProseMirror/prosemirror-tables/blob/master/src/schema.ts)
allow structures for which the separate
[TableMap computation](https://github.com/ProseMirror/prosemirror-tables/blob/master/src/tablemap.ts)
reports missing cells, collisions or overlong rowspans.

Check each original model, then inspect every table's `TableMap.get(table).problems`
before treating it as a valid table input. The finite fixtures below have known
span values; this is not a general hostile-input validator. No normalization or
automatic table repair is performed. Generic block comparison validates model
structure and does not promise application-specific table invariants.

TableMap positions are relative to the table's content. A cell's original
document position is `tableOuterStart + 1 + mapPosition`, separately on each
side. Map entries are not row/column identifiers or persistent cell IDs; a
spanning cell occupies several slots but remains one node.

## Observed capability and limits

- Cell text and same-text strong/link changes can be located through nested
  block details while retaining the complete table event. Metadata uses the
  corresponding original ranges.
- An inserted row remains an insertion in an appropriate child layer, not a
  command to apply directly to a table editor.
- Valid colspan and rowspan changes preserve both original tables. Two fixtures
  use official `EditorState`, `CellSelection` and `mergeCells` to generate real
  horizontal/vertical merges and assert that both original paragraphs survive.
  Separate layout-change fixtures deliberately remove a cell's content while
  changing the span; those are not presented as the command's merge behavior. Changed
  markup or multi-row gaps may stop refinement. In particular, the rowspan
  fixture produces a two-row-to-two-row replacement; no cell correspondence is
  inferred inside that gap.
- A caller who independently selects a layout-change fixture's first cell can inspect its
  span attributes through `compareNodeMetadata`. That explicit selection does
  not establish a general pairing algorithm or guarantee that applying a span
  attribute alone would produce a valid grid. In the real merge fixtures the
  selected cell contains an additional paragraph, so metadata-only comparison
  correctly rejects the changed content/structure.
- Repeated rows are tested for deterministic output, original ranges and
  reconstruction, not historical identity. Reverse comparison is checked on
  its own terms, without assuming symmetric edit choices.
- Unequal-width and overlong-rowspan negative fixtures pass `Node.check()` but
  produce TableMap problems. The integration skips comparison after this
  consumer preflight fails.

A consumer that already uses the official tables package can apply this
preflight to trusted, finite models before comparing:

```js
import {TableMap} from 'prosemirror-tables'

for (const doc of [oldDoc, newDoc]) {
  doc.check()
  doc.descendants(node => {
    if (node.type.spec.tableRole === 'table' && TableMap.get(node).problems?.length) {
      throw new RangeError('Original table grid requires validation or repair by its owner')
    }
  })
}
const result = compareDocumentBlocks(oldDoc, newDoc, {maxDepth: 4})
```

This does not run table-editor commands or silently repair either original.

Legacy `diffEditor` was also observed on both layout-change and both real-merge
fixtures. Its output passed model and grid checks for those four samples, but
its grid did not display the new spanning-cell layout. This is a visualization
limitation, not proof of general legacy table safety. Grid validity alone does
not prove that a review displays all semantic changes. Prefer the original-
preserving block result and explicit metadata where its contract applies.

## Verification and decision

After installing the checkout's locked development dependencies, run the opt-in
integration separately from the default unit suite:

```sh
node test/run-table-integration.mjs /absolute/path/to/npm-cli.js
```

The runner builds the library, copies the committed private manifest/lock from
`test/tables-runtime` to ignored `logs/tables-integration`, runs `npm ci` there
with install scripts disabled, and copies the same source and built artifacts
into that runtime. It never installs the project itself via a local file link.
The lock pins transitive dependencies as well as the tables/model versions.
All source and bundle consumers use matching official ESM or CommonJS model and
tables imports; a second installed model copy is rejected. Root dependencies
and the root lockfile remain unchanged.

The observed results are identical for source, CJS and ESM: nine valid scenarios,
two grid-invalid negative cases, and 79 checked comparison layers including
43 nested layers per format. These are integration cases/layers, not additional
unit-test counts. Full machine-readable evidence is written to
`logs/tables-integration/result.json`; the command prints the version/format
summary. Only this pinned profile and the tested Node runtime are established.

The handwritten runner and contract assertions are checked with TypeScript 5.9.3
checkJs using isolated Node declarations and the locked integration dependencies.
The source/CJS/ESM loader is exercised at runtime; generated Babel bundles are
not claimed to pass source checkJs. This is separate from the library source's
existing type check.

The integration validates source and built consumers with the matching official
model/table module instances. It independently walks original child boundaries,
checks event references and retained equal gaps, reconstructs every non-truncated
layer, verifies input immutability, and tests zero-budget/depth behavior. Known
grid dimensions and span occupancy provide an oracle separate from the diff.

No core defect was reproduced in these supported block/metadata contracts.
The useful delivery is a repeatable integration harness and a clear consumer
preflight/coverage recipe. No new pairing option, patch API, production dependency,
automatic grid repair or performance improvement is introduced. Editor plugins,
DOM rendering, selection commands and arbitrary custom table schemas remain
outside this model-level validation.
