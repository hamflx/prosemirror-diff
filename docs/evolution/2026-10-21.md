## Reproduction and fix

`normalizeNodeContent` groups adjacent text nodes into arrays. When a text run
is replaced by `hard_break` (or vice versa), `patchRemainNodes` passes the array
to `createDiffNode`. `mapDocumentNode` then reads `node.content.content` and
throws. All six new cases fail on the base with that error, while all 43 old
cases pass.

Expand either side with the existing `ensureArray` helper before marking each
node. This follows the existing unmatched-tail behavior, keeps deletion before
insertion, preserves original text marks, and changes no public signatures or
default diff mode. Tests cover both modes, both directions, a multi-node marked
Unicode run, input JSON immutability and nested block siblings. Each result
also passes ProseMirror `Node.check()`.

## Performance baseline

Run the same `test/benchmark.mjs` against base and patched source on the same
machine, sequentially. The harness warms each case 5 times then measures 25
individual calls with `performance.now()`, reporting sorted median and p95
(index 23). Each timed call includes input construction: string `repeat()` calls
for the text cases and document fixtures for the structural cases, as well as
the diff operation. Schema construction is outside the timed calls. Failures
are reported as errors, not timings.
Use Node 24 for direct source module detection. To reproduce the base, use a
separate checkout at the base commit with this harness copied in and the locked
dependencies installed; do not overwrite an active checkout.

| Case | Base median / p95 ms | Patched median / p95 ms |
| --- | ---: | ---: |
| unchanged ~2k UTF-16 units | 1.519 / 2.756 | 1.513 / 3.071 |
| repeated Unicode edit | 3.357 / 4.395 | 3.393 / 4.543 |
| unrelated 1000-character strings | 356.724 / 414.315 | 334.040 / 444.082 |
| text to leaf | TypeError | 0.023 / 0.080 |
| leaf to text | TypeError | 0.023 / 0.061 |

These are one-run descriptive measurements, not a speedup claim. Unchanged
text code paths show expected timing noise; rerun multiple processes before
making performance decisions. The unrelated-text case highlights future
worst-case investigation work.

## Limits and next decision

The existing renderer only diff-marks text descendants: a leaf such as
`hard_break` still has no insertion/deletion annotation. This fix prevents a
crash and retains the nodes; it does not promise structural reconstruction by
filtering diff marks. Attribute-only changes, default character-mode Unicode
boundaries, repeated-node matching and normalized arrays in matched spans need
separate reproductions. The placeholder `computeChildEqualityFactor` is another
review target. Next round should prioritize structural alignment and a precise
contract for leaf/attribute changes before expanding behavior.
