# Round 2 — use the public node-copy API

Base: `85c500cf0ccfde2367bffad8fe0299ca8d5a6b8d` (master).

## Evidence and decision

The previous round's TypeScript 5.9.3 checkJs audit exposed TS2554 at
`new Node(oldNode.type, oldNode.attrs, content, oldNode.marks)`.
The same diagnostic was reproduced on this base before the change.

The locked `prosemirror-model@1.18.1` source marks its Node constructor
`@internal`; its published `dist/index.d.ts` omits that constructor signature.
Its public [`Node.copy`](https://github.com/ProseMirror/prosemirror-model/blob/1.18.1/src/node.ts)
accepts a Fragment and preserves the node's type, attributes and marks.
For changed content, that implementation calls the same internal constructor
with the same values. This provides a direct public API replacement without
suppressing diagnostics or changing dependencies.

`NodeType.create` was also considered, but it recomputes attributes and
normalizes marks. `Node.copy` is a closer match for replacing content while
retaining existing markup. Explicit JSDoc parameter types ensure checkJs
checks the public method call rather than treating its receiver as `any`.

## Change and compatibility

`createNewNode` now returns `oldNode.copy(Fragment.fromArray(children))`.
Its arguments, exports, missing-type error and child-fragment normalization
are unchanged. Four compatibility tests cover mixed text/leaf children,
parent attributes and marks, input immutability, clearing content, empty
containers/leaves and the missing-type error. They guard runtime semantics;
the baseline type diagnostic is the failing reproduction for this change.

ProseMirror nodes are immutable. `copy` may return the original node when
the content Fragment is identical (notably an already-empty node), whereas
the previous constructor always allocated. Consumers must compare node
values rather than rely on this helper always returning a distinct object.
No new content validation is introduced. This helper operates on ProseMirror
nodes; arbitrary duck-typed objects without `copy` are not supported.

## Validation

Using the unchanged lockfile:

```sh
npm ci --ignore-scripts --no-audit --no-fund
node node_modules/vitest/vitest.mjs run
node node_modules/rollup/dist/bin/rollup -c rollup.config.mjs
npm exec --package=typescript@5.9.3 -- tsc --allowJs --checkJs --noEmit --target es2022 --moduleResolution bundler --module esnext --skipLibCheck src/diff.js
git diff --check
```

- Base audit: TS2554 at `src/diff.js(546,19)`; no other diagnostic.
- Patched audit: exit 0, no diagnostics, without new suppression directives.
- Tests: 53 passed across 3 files, including all 49 previous tests.
- Builds: UMD, CJS and ESM succeeded.
- Whitespace check: passed.

The audit covers the source entry specified above with existing compiler
options; it is not a claim of strict typing across the whole repository.
The benchmark was not rerun and no performance improvement is claimed.

## Next investigation

The type debt was prioritized because it had a precise reproduction and a
small public API fix. Structural alignment, repeated-node matching and
attribute-only changes remain open research topics; this change does not
resolve their behavior. Merge remains subject to independent review.
